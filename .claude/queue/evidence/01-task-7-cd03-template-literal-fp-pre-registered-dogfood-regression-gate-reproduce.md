## Task text

> Task 7 — CD03 template-literal FP (pre-registered, dogfood regression gate). Reproduce

> template literal (backtick string) produces a CD03 finding. If NO real case exists in
> corpus_v2 or prod dogfood data, mark this task done with evidence "not reproducible — no
> measured FP class" and do NOT change the detector (a fix without a failing case violates

## Reproduction (real, not synthetic)

Found in real prod dogfood source, not fabricated:
`mcp/source/services/repo-quality-gate-mcp/scripts/benchmark-local.mjs` (lines 91, 97,
103, 111) builds `.ts` fixture source via template literals, e.g.:

```js
Array.from({ length: 12 }, (_, index) => `export const generated${index} = ${index};`).join("\n") + "\n"
```

Before the fix, code-diet's CD03 detector (bare-text regex over raw source) scanned the
`.mjs` script itself and treated the `export const generated...` TEXT inside the backtick
string as a real declaration/reference, producing false CD03 findings attributed to the
generator script — which never actually declares those exports (they exist only in the
`.ts` string it writes out at runtime). Reproducible on-demand by feeding this exact file
to `analyzeSource`.

## TDD discipline followed (verify-red confirmed genuinely, via full rebuild)

Tests import from compiled `dist/detectors.js`, so verify-red required `git stash` +
`npm run build` (not just editing `src/`) to get a true pre-fix red state:

1. **Red (before fix):** stashed `src/detectors.ts`, rebuilt, ran
   `node --test test/detectors.test.mjs` → 2 of 17 tests failed exactly as expected
   (`CD03 does NOT flag an export declared only inside a template literal` and its mirror
   case), 15 passed. Confirmed genuine failure, not a stale-build artifact.
2. **Green (after fix):** restored `src/detectors.ts`, rebuilt, reran → all 17 passed.
3. Ran `grade-v2.mjs` on the green build → **v2a clean FP rate 0.110** (CI [0.063,0.186]),
   up from the documented §5d baseline of 0.100 — a measured regression, not within the
   original scope of the two red tests.
4. Root-caused it: the naive `blankTemplateLiterals()` blanked the ENTIRE backtick-string
   contents including `${...}` interpolations, which are real executed JS code, not
   string text. `corpus_v2/clean/zod/errors.ts` has
   `` `  -> at ${toDotPath(issue.path)}` `` — a genuine call to the exported `toDotPath`.
   Blanking it removed that real reference from the corpus scan, so `toDotPath` (and by
   the same mechanism `prettifyError`, which re-exports depend on transitively) newly
   registered as CD03 dead-export findings. Verified directly by running `analyzeSource`
   on `zod/errors.ts` before/after and diffing the finding set.
5. **Red again (for this new bug):** added test 3 above, confirmed it failed against the
   naive fix (`toDotPath` wrongly flagged).
6. **Fixed:** `blankTemplateLiterals()` now tracks `${...}` interpolation depth via brace
   counting and passes interpolated code through unblanked.
7. **Green again:** rebuilt, ran `node --test test/detectors.test.mjs` → **18/18 pass**.

## Result

Reproducible, real dogfood FP class confirmed and fixed under TDD (verify-red → fix →
verify-green), including a self-caught secondary regression (interpolated-code-in-
template-literal wrongly treated as non-code) that was itself caught by the grader gate

needed since the final number is exactly identical to baseline.

## Remaining risks

- `blankTemplateLiterals()` is a single-level, brace-counting scan (no real parser): a
  string or regex literal containing an unbalanced `}` *inside* a `${...}` interpolation
  (e.g. `` `${cond ? "}" : "x"}` ``) could under-count interpolation depth and leak text
  scanning into what should still be interpolated code, or vice versa. This is called out
  explicitly in the function's doc comment as an accepted limitation consistent with the
  project's stated text-based-analysis scope (no case of this shape was found in any
  corpus file during this task).
- Nested template literals *inside* an interpolation (`` `a${`b${c}`}` ``) are passed
  through as opaque code rather than recursively re-scanned; this only matters if such a
  nested literal itself both declares an `export` and needs blanking, which did not occur
  in any reproduced or corpus case.
- CD03's overall precision ceiling on injected/library-style code (v2b P=0.39) is
  unchanged and out of scope for this task — it is the pre-existing, pre-registered §5b/
  §5d finding, not something task 7 was asked to fix.
